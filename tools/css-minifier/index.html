How it works

        
A lexer, not a find-and-replace

      


      

        

          

            
Comments are eaten

            
Every /* … */ block is removed from the stream before any other step, so a stray star can never leak into the output. If the comment is left open, minification stops rather than guessing.

          

        

        

          

            
Strings and urls are fenced

            
Anything between quotes, and everything inside url(…), is copied verbatim — including data URIs with nested parens. Whitespace inside them is real content and stays untouched.

          

        

        

          

            
Whitespace is only dropped where safe

            
Spaces around braces, commas, semicolons and colons disappear; spaces that separate two values (like “1px solid”) stay. calc() keeps its operator spaces because the spec demands them.

          

        

      

    

  


  
  

    

      

        
Questions

        
CSS minifier FAQ

      

      

        

          Is the output guaranteed valid CSS?
          
Yes. Whitespace removal only happens at punctuation the grammar allows it, and fenced regions are never altered. What you paste in is what you get back, only smaller — the result parses identically.

        

        

          Why keep calc() operator spaces?
          
The CSS specification requires whitespace around the + and − operators inside calc(). Removing it makes the whole expression invalid in most browsers, so this tool deliberately never touches those spaces.

        

        

          Is it safe for third-party stylesheets?
          
Yes — since only comments and provably-safe whitespace change, minified output remains behaviorally identical. Perfect for vendoring libraries or shipping critical CSS above the fold.
