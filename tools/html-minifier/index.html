How it works

        
Token by token, never a regex bomb

      


      

        

          

            
Comments go first

            
HTML comments are matched by their exact start and end markers and dropped from the output — unless you keep them, which is the same protection going the other way.

          

        

        

          

            
Whitespace collapses smartly

            
Indentation and blank lines disappear. Where a space is rendered between inline elements it is kept as exactly one space, so <b>a</b> <i>b</i> stays readable.

          

        

        

          

            
Protected blocks never change

            
The tokenizer recognizes <pre>, <textarea>, <script> and <style> and copies their bodies bit-for-bit — spacing inside them is content, not decoration.

          

        

      

    

  


  
  

    

      

        
Questions

        
HTML minifier FAQ

      

      

        

          Will minifying change how my page displays?
          
No. Only comments, indentation and whitespace are removed, and inline gaps keep a single space. Since rendering collapses consecutive whitespace anyway, the visual result is identical.

        

        

          Why are script and style bodies left alone?
          
Javascript and CSS have their own rules — one removed newline can turn a comment into code. This tool only manages markup, so it never rewrites the insides of a code block.

        

        

          Where does the percent saving come from?
          
It is the drop in byte count between the original and the output, measured with UTF-8 byte sizes so non-ASCII characters don't lie about the real weight of the page.
