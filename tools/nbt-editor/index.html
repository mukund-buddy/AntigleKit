Reference

Every NBT file Minecraft writes

NBT (Named Binary Tag) is one format with several encodings, and every Minecraft edition, launcher and server core uses a different combination of them. This editor implements all of them and picks the right one from the bytes themselves, so you never have to know which variant a file is before you open it.

Guide

How to edit an NBT file

  1. Get the file off the server or device. Java servers keep it in world/, Bedrock servers in worlds/YourWorld/, Android in games/com.mojang/minecraftWorlds/<id>/. Stop the server first so the file is not being written while you copy it.

  2. Drop it into the editor. The badge above the tree tells you what was detected — edition, encoding, compression and, for Bedrock, the storage version from the header.

  3. Edit. Tap a value to change it in place. Use search to jump to a tag by name or value, + to add tags to any compound or list, × to remove them.

  4. Save & Download. The output format and compression selectors default to whatever the file arrived as, so a plain edit is a byte-faithful round trip.

  5. Put it back and restart. Keep the original as a backup until the world has loaded once and looks right.

Under the hood

What this editor handles

  • All five encodings — Java big-endian, Java network (nameless root), Bedrock level.dat (8-byte header), Bedrock raw little-endian, and Bedrock network varint.
  • All 13 NBT tag types with real 64-bit TAG_Long precision — no rounded doubles.
  • gzip, zlib and raw compression, straight through the browser's built-in Compression Streams API.
  • In-place value editing, tag add/remove, array editing, search by name or value, and SNBT export.
  • Nothing ever leaves your device — the file is parsed and written by JavaScript in your browser.
Questions

Questions & answers

Is this NBT editor free?

Yes. Every tool on AntigleKit is free and runs entirely in your browser. Nothing is uploaded, stored, or processed on a server.

Which files can it open?

Any NBT file, from any edition: level.dat, playerdata/*.dat, structure .nbt, Bedrock .mcstructure, WorldEdit .schem and legacy .schematic, LevelDB values, region payload chunks and packet dumps. The engine detects the encoding, byte order, header and compression from the bytes themselves.

Does it support both Java and Bedrock?

Yes — big-endian Java (Vanilla, Paper, Spigot, Fabric, Forge and the rest) and little-endian Bedrock (BDS, PocketMine-MP, Nukkit) including the 8-byte level.dat header, plus varint network variants.

Will it corrupt my world?

The editor writes a new download rather than touching the file you drop in. Keep a backup until the world has loaded once, stop the server before copying, and edit values rather than tag types or names.

Why does it need a modern browser?

TAG_Long uses BigInt and gzip/zlib use the Compression Streams API, so a current version of Chrome, Edge, Firefox or Safari is required. Older browsers will report a clear error.
